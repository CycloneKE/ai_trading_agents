# Runtime dependencies for the production container.
#
# This is the file the Dockerfile installs. It is NOT requirements.txt, and
# that distinction has bitten this project once already: PyJWT and bcrypt were
# in requirements.txt and in requirements-ci.txt (added there with the comment
# "Auth stack"), but never here. src/api/auth.py imports both at module scope
# with no guard, so every deployed container answered protected routes with
# 503 and nobody could log in to the dashboard, while CI stayed green because
# CI installs requirements-ci.txt.
#
# The rule that follows from that: anything imported WITHOUT a try/except
# guard on the agent or API startup path belongs here. Optional, degrading
# imports (torch, transformers, nltk, pandas_ta) deliberately do not.
# tests/test_runtime_requirements.py enforces it.

# --- Core web and process layer -------------------------------------------
flask>=3.1.3
flask-cors>=6.0.5
waitress>=3.0.0          # Production WSGI server. Without it api_server falls
                         # back to the Flask development server, which prints
                         # its own warning not to use it in production.

# --- Authentication -------------------------------------------------------
# Both are imported unguarded by src/api/auth.py. Missing either one locks the
# entire API down: AUTH_AVAILABLE goes False and protected routes return 503.
PyJWT>=2.14.0
bcrypt>=4.0.0

# --- Configuration and transport ------------------------------------------
python-dotenv>=1.2.3
requests>=2.34.2
websocket-client>=1.9.2
aiohttp>=3.14.3
cryptography>=3.4.8

# --- State and metrics ----------------------------------------------------
redis>=8.1.0
psycopg2-binary>=2.9.13
prometheus-client>=0.26.0
psutil>=7.2.2            # System metrics only. The monitoring service and the
                         # /health endpoint run without it.

# --- Numeric ---------------------------------------------------------------
numpy>=2.5.3
pandas>=1.3.0

# Also required, not optional. src/agent/risk_calculator.py imports
# `from scipy import stats` and `from scipy.optimize import minimize` at
# module scope, and src/agent/main.py imports RiskCalculator at module scope,
# so the process cannot start without it. Found by the import-graph walk in
# tests/test_runtime_requirements.py immediately after the yfinance fix: it
# would have been the next crash loop.
scipy>=1.18.1

# --- Market data -----------------------------------------------------------
# Required, not optional, despite what this file used to claim.
#
# src/utils/real_price_feed.py imports yfinance at module scope with no
# guard, and the startup path reaches it unconditionally:
#
#     src/agent/main.py
#       -> src/agent/broker_manager.py       (module scope)
#         -> src/agent/paper_trading.py      (module scope)
#           -> src/utils/real_price_feed.py  (module scope)
#             -> import yfinance
#
# Listing it as optional here put it in requirements.txt and
# requirements-ci.txt but not in the image, so the tests passed, the image
# built, and the container crash-looped on the server with
# ModuleNotFoundError. Exactly the failure PyJWT and bcrypt caused before it.
yfinance>=0.2.60

# --- Paid AI tier ---------------------------------------------------------
# Claude, via the official SDK. Imported only when ANTHROPIC_API_KEY is set
# (src/agent/claude_provider.py), so the agent starts without it; it is here
# so that setting the key is all it takes to switch the paid tier on.
anthropic>=1.8,<2

# --- Brokers ----------------------------------------------------------------
# No broker SDK is listed, and none is needed. All three connectors
# (alpaca, coinbase, oanda) talk to their REST APIs with `requests`, above.
#
# src/connectors/alpaca_broker.py used to import `alpaca-trade-api`, which was
# never installed here, so BrokerManager's guarded import failed, the 'alpaca'
# type was never registered, and the broker that config/config.json marks
# `primary` did not exist. Orders went to the internal simulator and the logs
# said only "Unknown broker type: alpaca".
#
# Adding that SDK was the obvious fix and the wrong one: version 0.48 pins
# `urllib3 < 1.25`, forcing urllib3 1.24.3 (2019) underneath `requests`, which
# is the HTTP stack that carries the API credentials. It also pulls in
# alpha-vantage, asyncio-nats-client and peewee. The connector made seven
# calls, all of them plain REST endpoints, so the dependency bought nothing.

# --- Optional features the dashboard offers --------------------------------
# Guarded imports, so the agent starts without them, but then the feature is
# silently off on the server. Both are small (about 40 MB together).
pdfplumber>=0.11.0       # Research page: reading uploaded broker research PDFs
pypdf>=4.0               # Research page: the Market Pulse scorecard keeps its numbers whole
                         # with pypdf (src/agent/market_pulse.py); pdfplumber is the fallback.
                         # (src/utils/pdf_parser.py). Without it every upload
                         # failed with "PDF extraction will be disabled".
vaderSentiment>=3.3.2    # News sentiment (src/agent/sentiment_analyzer.py).
                         # Without any backend every headline scored neutral,
                         # and the sector specialists read neutral sentiment.

# --- Deliberately absent -----------------------------------------------------
# Each is guarded at its import site; the startup log names what is off.
#   scikit-learn, joblib: only the DQN and supervised-learning strategies,
#     neither enabled in config/config.json, and the AutoML optimizer, which
#     nothing calls.
#   cvxpy: the portfolio optimizer, which writes a daily report nothing reads.
#   nltk: the NLP manager, which nothing calls; the sentiment analyzer works
#     without it.
#   torch, transformers (FinBERT): gigabytes of image and memory for a
#     finance-tuned sentiment model; VADER above covers the dashboard.
#   supabase: the journals live on the server's own disk.
# See scripts/requirements-ml.txt and docs/COOLIFY_DEPLOYMENT.md.
